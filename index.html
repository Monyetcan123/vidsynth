PIPELINE & CLOUD TOPOLOGY

Technology & Proposed Infrastructure Architecture

In accordance with our engineering transparency standards, we clearly separate capabilities implemented in this web application from our proposed cloud GPU rendering infrastructure.

● IMPLEMENTED IN STUDIO ◌ PROPOSED CLOUD DEPLOYMENT
01 // CHARACTER TRANSFORMATION SPECIFIED

Spatial ControlNet + Identity Lock

Decouples structural pose and facial landmark geometry from surface texture synthesis, preventing facial distortion during steep head turns.

02 // VIDEO SEGMENTATION SPECIFIED

Sub-Pixel Trimap & Semantic Mattes

Generates isolated alpha channels for cranial mesh, garments, and props so background plates remain untouched until final composite.

03 // DEPTH ESTIMATION SPECIFIED

16-Bit Disparity & Normal Relighting

Predicts dense metric Z-depth per frame to guide virtual rim and key light interaction across synthesized materials.

04 // TEMPORAL CONSISTENCY SPECIFIED

Bi-Directional Optical Flow Warping

Enforces cross-frame latent attention weighted by RAFT optical flow motion vectors across 16-frame sliding windows.

05 // AUTH & TENANT DATA LAYER IMPLEMENTED

Supabase PostgreSQL + Row Level Security

Complete schema (`001_initial_schema.sql`) with strict per-user RLS policies for profiles, projects, render job logs, and credit ledgers.

06 // DISTRIBUTED RENDERING PROPOSED ARCHITECTURE

Asynchronous Batch GPU Workers

Designed to dispatch multi-pass conditioning jobs to containerized GPU worker nodes via asynchronous job queues.

PROPOSED INFRASTRUCTURE ARCHITECTURE (CLOUD DEPLOYMENT BLUEPRINT)

Target AWS Production Topology for Distributed GPU Rendering

STATUS: ARCHITECTURAL SPECIFICATION (NO FAKE TELEMETRY)
COMPUTE TIER (PROPOSED)
Amazon EC2 GPU Instances

Target `g5.2xlarge` / `p4d` inference nodes for running UNet-3D diffusion, RAFT optical flow, and ViT-Matte passes.

ORCHESTRATION (PROPOSED)
AWS Batch Job Queue

Asynchronous scheduling of frame-chunked conditioning jobs with spot/on-demand scaling based on queue depth.

MEDIA STORAGE (PROPOSED)
Amazon S3 Asset Buckets

Pre-signed URL ingest for source plates and lifecycle-managed storage for 16-bit OpenEXR / ProRes output sequences.

OBSERVABILITY (PROPOSED)
Amazon CloudWatch

Worker container logging, frame render duration metrics, and dead-letter queue alerting for failed conditioning passes.
