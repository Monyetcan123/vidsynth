SECTION 01 // APPLICATION SECURITY

Security Overview & Scope Disclosure

ACCURATE SCOPE STATEMENT

VidSynth is engineered with strict separation between public client code and privileged backend operations. In accordance with our transparency rules, we document only the security controls implemented in this codebase and do not claim unverified third-party compliance certifications (such as SOC 2, ISO 27001, or formal GDPR certification).

ROW LEVEL SECURITY (RLS)

All PostgreSQL tables (`profiles`, `projects`, `render_jobs`, `credit_ledger`) enforce `auth.uid() = user_id` policies in `001_initial_schema.sql` so tenants can never query or mutate another user's records.

CREDENTIAL ISOLATION

Browser JavaScript uses only the public Supabase `anon` key combined with user JWT sessions. Privileged `service_role` keys are strictly prohibited from frontend bundles.

SECTION 02 // MEDIA LIFECYCLE

Data Processing for Source Videos, Generated Content & Accounts

1. Uploaded Source Plates & Conditioning Inputs: Source footage, depth maps, and segmentation masks configured within a Studio project are scoped strictly to the owning account ID. Customer media is processed solely to execute requested conditioning passes and is never used to train shared foundation models without explicit written authorization.

2. Synthesized Video & Multi-Pass Outputs: Generated MP4, WebM, ProRes, and 16-bit OpenEXR sequences are associated with the user's project record. When a project is deleted via the Studio Dashboard, its project metadata record is removed immediately.

3. Account & Telemetry Records: Account profiles store full name, email address, organization name, and credit ledger history required for session authentication and usage accounting.

SECTION 03 // PRIVACY

Privacy Policy

VidSynth collects only the information you explicitly provide when registering an account, configuring a project, or submitting an Early Access inquiry (`full_name`, `work_email`, `company`, `use_case`).

In Local Sandbox Mode, account and project records are stored exclusively inside your browser's `localStorage` and are never transmitted to third-party analytics trackers. When connected to a configured Supabase instance, data is stored in your designated PostgreSQL database under RLS protection.

SECTION 05 // BROWSER STORAGE

Cookie & Local Storage Policy

VidSynth uses functional browser storage (`localStorage` and `sessionStorage`) strictly for maintaining authenticated session tokens (`vidsynth_active_session_v1`), persisting announcement bar dismissal states, and storing Sandbox project configurations. No third-party advertising cookies are used.
