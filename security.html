INSTITUTIONAL SECURITY DOCUMENTATION

Security Overview

● IMPLEMENTED CONTROL ◌ PLANNED CONTROL ◆ SECURITY PRINCIPLE

This Security Overview documents the actual security posture of VidSynth AI (https://vidsynth.app) for institutional reviewers, cloud program evaluators, and prospective pilot partners. We do not claim unverified third-party security certifications, formal penetration testing attestations, or unimplemented compliance frameworks. Instead, we distinguish transparently between controls active in our codebase today, controls planned for our cloud compute infrastructure, and our guiding engineering principles.

1. Security Philosophy 2. Application Architecture 3. Data Transmission 4. Encryption in Transit 5. Processing Pipeline Security 6. Data Retention 7. Access Control 8. Third-Party Infrastructure 9. Security Incident Communication 10. Responsible Disclosure 11. Security Contact
SECTION 01 ◆ SECURITY PRINCIPLE

1. Security Philosophy

Our security philosophy is grounded in attack-surface minimization, separation of responsibilities, and verifiable transparency. Rather than exposing unbacked login portals, unverified upload endpoints, or client-side database credentials during our preview stage, we restrict our public web surface to deterministic, read-only R&D demonstrations and handle pilot onboarding through verified direct communication.

SECTION 02 ● IMPLEMENTED CONTROL

2. Application Architecture

The VidSynth AI architecture strictly separates the public frontend presentation layer from backend compute and database systems:

  • Implemented Public Frontend (vidsynth.app): Delivered as a static HTML5, CSS, and vanilla JavaScript application running in Sandbox Preview Mode. All interactive comparison viewports, frame-steppers, and camera trajectory previews operate on pre-rendered local reference media (assets/videos/*.webm) inside the user's browser.
  • Zero Client-Side Secret Exposure: No private API keys, cloud storage credentials, or privileged database service_role tokens are embedded in browser JavaScript (config/config.js, js/app.js, js/video-comparison.js).
  • Prepared Relational Schema (supabase/migrations/001_initial_schema.sql): Repository includes a prepared PostgreSQL schema with Row Level Security (auth.uid() = user_id) policies designed for future authenticated tenant deployment once backend services are provisioned.
SECTION 03 ● IMPLEMENTED & ◌ PLANNED

3. Data Transmission

Implemented (Public Website): Browsing https://vidsynth.app transmits only standard HTTP GET requests to fetch static HTML, CSS, JavaScript, font, and reference video assets. Early access inquiries initiated via our website use standard mailto: links that open your local email client; no form payloads are transmitted silently to unverified third-party webhook servers.

Planned (Pilot & Enterprise API Communication): For cloud rendering workflows, API communication between authorized client workspaces and backend orchestration endpoints is designed to occur exclusively over authenticated HTTPS endpoints using short-lived, scoped tokens and pre-signed object storage URLs.

SECTION 04 ● IMPLEMENTED CONTROL

4. Encryption in Transit

Public web traffic to https://vidsynth.app and external stylesheet/font dependencies (https://fonts.googleapis.com, https://cdn.tailwindcss.com) is served over HTTPS using Transport Layer Security (TLS) managed by the underlying hosting and CDN infrastructure.

Note on Encryption at Rest: Because the public website is a static frontend without an active customer database or media upload server, we do not make claims regarding customer database encryption-at-rest configurations at this stage. Encryption at rest for pilot media buckets will be configured and documented per cloud provider capabilities upon cloud storage deployment.

SECTION 05 ◌ PLANNED CONTROL

5. Processing Pipeline Security

Our neural visual effects conditioning pipeline (supporting VS-CHAR-2.4, VS-MATTE-3.0, VS-RELIGHT-1.2, VS-IDLOCK-2.1, and VS-TEMPORAL-1.5) is designed around controlled processing environments:

  • Workload Isolation (Planned): Batch GPU conditioning jobs are architected to run in isolated container environments that process a single project job specification per task invocation.
  • No Cross-Tenant Model Training (Principle): Customer source plates submitted during pilot or commercial evaluations are segregated from shared model training datasets unless explicitly authorized in writing.
SECTION 06 ◆ PRINCIPLE & ◌ PLANNED

6. Data Retention

Temporary Media Handling Principle: Intermediate conditioning passes (such as temporary optical flow vectors, uncompressed frame buffers, and scratch trimaps generated during rendering) are intended to be treated as ephemeral scratch data and purged upon job completion.

Pilot & Correspondence Retention: During manual Early Access Pilot evaluations, source plates and rendered deliverables are retained only for the duration agreed with the participating studio or researcher, and may be deleted upon request to founder@vidsynth.app. Automated object-storage lifecycle expiration policies are planned for production cloud deployment.

SECTION 07 ◆ SECURITY PRINCIPLE

7. Access Control

We follow the principle of least-privilege access:

  • Repository & Domain Administration: Administrative access to the vidsynth.app domain configuration, source repository, and official founder correspondence (founder@vidsynth.app) is restricted to project leadership.
  • Credential Management: Environment configuration templates (config/config.example.js) explicitly prohibit committing private credentials or service keys to source control.
  • Tenant Isolation (Planned): When multi-tenant cloud workspaces are enabled, database queries are scoped via PostgreSQL Row Level Security (RLS) policies tied to verified user session identifiers.
SECTION 08 ● IMPLEMENTED

8. Third-Party Infrastructure

VidSynth AI relies on established third-party infrastructure providers for static web hosting, DNS routing, typography delivery (Google Fonts), and planned cloud GPU compute. While we select reputable infrastructure providers, physical data-center security and network backbone resilience are managed by those respective providers under their published security programs.

SECTION 09 ◆ SECURITY PRINCIPLE

9. Security Incident Communication

In the event of a confirmed security incident affecting confidential pilot media assets or partner correspondence held by VidSynth AI, we will investigate the scope of the incident, take remediation steps to contain the issue, and notify affected pilot participants or partners via email without unreasonable delay and in accordance with applicable legal obligations.

SECTION 10 ● ACTIVE POLICY

10. Responsible Disclosure

We welcome reports from security researchers and institutional reviewers who identify potential vulnerabilities on https://vidsynth.app. If you discover a security issue, please report it privately to founder@vidsynth.app with:

  • A clear description of the issue and affected URL or component;
  • Steps required to reproduce the behavior; and
  • Reasonable time for us to investigate and remediate the issue before public disclosure.

Please do not perform denial-of-service testing, automated high-volume scanning against third-party hosting infrastructure, or social engineering when evaluating our site.
